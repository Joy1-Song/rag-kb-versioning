# 工程细节

README 讲策略和结果，这里记录实现上的约束和边界。

## 两条流程

```text
入库：上传 -> 校验参数 / 索引签名查重 -> 解析 / 切分 -> 登记写入意图（writing）
      -> Embedding / Chroma 写新版本 -> 标记 ready -> 删除旧版本 -> 原子更新登记表

问答：问题 -> 参数校验 -> 检索（默认纯向量，可选 hybrid）-> 过滤空白片段
      -> 无剩余证据：程序直接回答资料不足
      -> 有证据：拼接片段原文与提示词 -> 模型生成 -> 展示答案与来源 -> 记录日志
```

| 文件 | 职责 |
|---|---|
| `app.py` | Streamlit 上传与问答页面、会话状态、异常提示、人工评测入口 |
| `src/rag_service.py` | 串联入库与问答；参数校验、空白片段过滤、无证据短路 |
| `src/ingestion.py` | 索引签名、版本化写入、文件锁、写入日志与恢复 |
| `src/file_registry.py` | 本地登记表 |
| `src/vector_store.py` | Chroma 写入、Top-k 检索、混合检索入口 |
| `src/hybrid_search.py` | 字符 2–4 gram TF-IDF 与 RRF 融合，不额外调用模型 |
| `src/retrieval_metrics.py` | 文档级 Hit@k、Recall@k、MRR |
| `src/document_loader.py`、`src/splitter.py` | TXT / Markdown / PDF 解析，按字符长度切分，保留来源与页码 |
| `src/llm_client.py`、`src/config.py` | 模型客户端；路径与环境配置 |
| `src/logger.py`、`src/evaluator.py` | 问答与请求 CSV 日志；关键词子串检查 |

## 版本化入库

- **文档身份：** 文件名是文档身份。同名新内容表示替换，不同文件名即使内容相同也分别保留来源。切分参数、Embedding 模型或处理版本变化时会重建，不只凭字节哈希跳过。
- **写入顺序：**
  1. 写向量前，把新旧片段 ID 和 `writing` 状态原子保存到登记表。
  2. 新片段全部写入成功后保存 `ready`，再清理旧片段、提交文件记录。
  3. 入库或检索前先恢复日志：`writing` 删除未提交的新片段，`ready` 继续清理旧片段。恢复失败时阻止检索，不展示混合版本。
- **重复与并发：** 相同请求复用确定性的片段 ID；文件锁覆盖本应用的线程和进程，等待默认 10 秒。
- **升级旧数据：** 旧版登记表没有模型标识，不直接视为兼容。模型未变时，重新上传原登记表中的全部文件即可完成升级；只升级了部分文件时暂不开放检索。模型改变时，需要另建登记表和向量库。
- **边界：** 这是可恢复的本地写入协议，不是跨 Chroma 和 JSON 的 ACID 事务。中断后重试可能重新计算 Embedding；不能协调绕过本服务直接写 Chroma 的程序；没有分布式锁或多租户隔离。

## 生成前的边界

- 拒绝空问题、非整数或小于 1 的 `top_k`、未知检索模式。
- 先过滤只有空白字符的片段；没有剩余证据时，由程序返回固定文本，不调用模型。
- 检索或模型异常照常抛出，不伪装成「资料不足」。
- 不判断非空片段是否相关（见 CASES 第 4 条），也不校验回答结论是否被引用支持（见 CASES 第 5 条）。

## 日志

| 文件 | 内容 |
|---|---|
| `outputs/logs.csv` | 成功返回的问答、片段 ID、来源、耗时 |
| `outputs/request_logs.csv` | 每次提问的请求 ID、状态、错误类型、耗时、Top-k；失败也记录 |

- `status=success` 只表示调用正常完成，不代表答案正确。失败时只记录异常类型，不写异常详情。
- 一行表示一次应用层提问，不对应底层 HTTP 请求。
- 日志写盘失败时页面会提示，不丢弃已得到的答案。日志可能包含用户问题和资料内容，已被 `.gitignore` 排除。

## 页面评测字段

页面右侧的评测面板只做关键词子串匹配，不是语义判断：

- `answer_correct` 的含义是关键词命中率至少 80%，不代表事实正确。
- `completeness_score` 记录的是关键词命中率。
- `gold_answer`、`citation_valid` 保存人工输入，程序不自动核对。

未填关键词时命中率记为 0，应视为没有做检查。

## 测试

`python -m pytest tests -q`：54 项离线测试，覆盖以下内容：

- 页面状态：超时后清理旧答案、初始化失败、缺少 Key、日志写盘失败；
- 文档转换与片段元数据；
- 版本化入库：写盘故障、清理失败、旧索引升级、缺失登记表、真实本地 Chroma；
- 混合检索与索引缓存刷新；
- 日志格式。

页面测试用假的 RAG 服务并阻断网络；Chroma 集成测试用离线哈希向量，只验证存储行为。这些测试不验证 PDF 解析质量、语义召回效果或回答质量。
